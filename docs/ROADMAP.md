# 接續工作與發布閘門

## P0：先取得可用性與資料安全的真實證據

在允許本機 origin 的環境完成 npm run verify:release，修復真實 E2E 找到的問題，不改弱測試。用 iOS/Android 實機測密語、IndexedDB、長時間背景切換、儲存失敗、2 分頁、離線冷啟動、版本更新。由目標使用者驗證 TalkBack/VoiceOver、5–10 秒目標及疲倦時的負擔。資安／臨床／隱私告知做專業審查。這是對外收集真實健康資料前的優先事項。

## P1：更細緻但不犧牲最低記錄

現在是每日摘要，可修正並保留歷史，但不是一天多場 headache event。新增真正多事件時，要有 event ID、發生時間區間、實際輸入時間、每欄位來源、跨日事件與舊資料 migration；不可把原每日摘要偽裝成一個精確開始的事件。再支援「只記得最近幾天、不知道哪天」的區間式回憶，不強迫發明日期。

每日場景、睡眠、藥物、處置可記，但本版不做統計混淆調整。未來個人模式需要缺失機制、前瞻／回溯敏感度分析、資料稀疏時不輸出結果、校準與使用者理解研究。不要把啟發式升級成診斷分數。

增加自主選擇的常用症狀排序、提醒日常事件錨點與更細緻暫停。只在有明確益處與使用者同意下做本機適應；不以 app 未開啟推定症狀，不以更多提醒補償低能量。

## P2：獨立評估的可選產品

原生通知動作、穿戴、HealthKit/Health Connect、可靠本機語音、多裝置端對端加密同步、研究捐贈、正式 DRSP/C-PASS 模組、無障礙產品教育／QR、標記正確的 PDF 均需獨立規格、同意、測試與平台驗證。原生平台 API 不等於純 PWA 可以直接達成；不要放看似可用的假開關。

正式量表的題目、選項、順序、回憶期間與分數不可任意更動；需處理授權、版本、臨床方案，與本版個人模式隔離。即時聲明、缺失與補登分開。不以泛用生成式 AI 代替診斷。

## 長期不做的預設

第三方廣告 SDK、session replay、強制註冊、預設性生活／懷孕問題、強制照顧者共享、用中斷打卡羞辱、以生理期推測個性／工作能力、自動攝影經血或私密部位、用症狀宣告經期開始／安全期。這些不是「尚未開發所以可以隨便加」的功能。
